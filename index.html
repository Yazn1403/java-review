UNIT 01 - SLIDES COMPREHENSIVE REVIEW

Java Introduction & Ecosystem

1. مفهوم البرنامج وتشبيهه بسلايدات المقرر (Concept of a Program)

البرنامج في أصله هو set of instructions يوجه الحاسوب لأداء المهام وإنتاج المخرجات المطلوبة. تشرح السلايدات هذا المفهوم بتشبهيه بدقة بـ وصفة الطهي (Recipe):

المكونات Ingredients

تطابق المتغيرات Variables التي تخزن البيانات بالذاكرة.

خطوات التحضير Directions

تطابق الجمل البرمجية والتعليمات Statements التي تنفذ بالتسلسل.

2. الفرق الدقيق بين المترجم والمفسر (Compiler vs Interpreter)
Java Compiler (javac)

يقوم بمسح وترجمة ملف المصدر بالكامل .java دفعة واحدة قبل بدء التنفيذ، وينتج ملف البايت كود الوسيط .class.

Java Interpreter (JVM)

يقوم بقراءة تعليمات ملف البايت كود وتفسيرها وتحويلها إلى لغة الآلة المباشرة **سطراً بسطر** أثناء تشغيل البرنامج.

3. مكونات بيئة التشغيل والتطوير (JDK vs JRE vs JVM)
1. JVM (Java Virtual Machine):

البيئة الافتراضية المسؤولة عن تنفيذ الـ Bytecode على المعالج وتوفر ميزة Write Once, Run Anywhere.

2. JRE (Java Runtime Environment) = JVM + Class Libraries:

يحتوي الآلة الافتراضية إضافة إلى المكتبات الأساسية لتشغيل برامج جافا على أجهزة المستخدمين.

3. JDK (Java Development Kit) = JRE + Development Tools (javac):

الحزمة الكاملة الموجهة للمبرمجين وتحوي المترجم (javac) وأدوات التطوير والبناء.

UNIT 02 - SLIDES COMPREHENSIVE REVIEW

Algorithms, Flowcharts & Error Types

1. رموز مخططات التدفق المعرفية (Flowchart Symbols)
Oval (بيضاوي) بداية أو نهاية المخطط (Start/End).
Parallelogram (متوازي) عمليات الإدخال والإخراج (Input/Output).
Rectangle (مستطيل) عمليات المعالجة والحساب (Processing).
Diamond (معين) القرارات والشرط (Decision IF/ELSE).
2. الشرح العميق لأنواع الأخطاء البرمجية الثلاثة (Types of Errors)
1. Syntax Errors (أخطاء القواعد النحوية)

مخالفة قواعد اللغة الصارمة. يكتشفها المترجم ويمنع إنشاء البايت كود.

مثال: System.out.println("UQU") // نسيان ; في نهاية الجملة

2. Runtime Errors (أخطاء التشغيل)

أخطاء تحدث أثناء تشغيل البرنامج فعلياً وتؤدي إلى توقف البرنامج المفاجئ (Crash).

مثال: int res = 10 / 0; // القسمة على صفر

3. Logic Errors (الأخطاء المنطقية)

يعمل البرنامج وينتهي بسلام ولكن النتائج خاطئة تماماً. المترجم والكمبيوتر لا يكتشفانها بل يتطلب ذلك اختبار المبرمج.

مثال: حساب مساحة مستطيل بجمع الطول والعرض بدلاً من ضربهما.

شروط تسمية المعرفات والثوابت (Identifiers & Final)
شروط المعرفات Identifiers:

تُقبل الأحرف، الأرقام، الشرطة السفلية _، أو علامة $. يُمنع البدء برقم نهائياً، ولغة جافا حساسة للحالة Case-Sensitive.

الثوابت Named Constants:

يتم تجميد تغيير قيمتها باستخدام final وتُكتب بأحرف كبيرة كعُرف برمجي:

public static final double TAX_RATE = 0.15;
UNIT 04 - SLIDES COMPREHENSIVE REVIEW

Expressions, Casting & Operators

التوافق والتحويل القسري (Assignment Compatibility & Type Casting)
التوافق التلقائي (Automatic Compatibility):

تحويل القيمة من النوع الأصغر إلى النوع الأكبر يميناً يتم تلقائياً دون فقدان بيانات:

byte → short → int → long → float → double

التحويل القسري (Type Casting):

عند التحويل العكسي من أكبر إلى أصغر، يتطلب ذلك كتابة النوع بين قوسين ويتم **قطع الكسر العشرية بالكامل (Truncation)** دون تقريب:

double avg = 9.99;
int roundedAvg = (int)avg; // roundedAvg = 9
ترتيب أولويات العمليات الحسابية (Precedence Rules)
  1. الأقواس Parentheses (): تُحسب أولاً من الداخل للخارج.
  2. الضرب والقسمة وباقي القسمة (* / %): من اليسار لليمين.
  3. الجمع والطرح (+ -): من اليسار لليمين.
  4. معامل التعيين (=): يُنفذ في نهاية المعادلة.
UNIT 05 - SLIDES COMPREHENSIVE REVIEW

Scanner & Printf Formatting

🔴 الشرح التفصيلي لفخ nextLine() العالق بعد nextInt()

لماذا يحدث هذا الفخ في الاختبارات؟

عند قراءة عدد بـ nextInt()، يقرأ Scanner الأرقام فقط ويترك زر الإدخال '\n' عائماً في الذاكرة المؤقتة. وعند استدعاء nextLine() بعدها، تقرأ هذا الرمز فوراً وتعتبر أن النص فارغ دون انتظار إدخال المبرمج!

الحل المعتمد في السلايدات:

int age = keyboard.nextInt();
keyboard.nextLine(); // امتصاص السطر الفارغ العالق '\n'
String name = keyboard.nextLine(); // قراءة الاسم بنجاح
